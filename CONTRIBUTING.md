# Contributing

Contributions should make the language more understandable and more usable, not merely add more decoration.

Before adding a component or example:

1. Explain the product problem it solves.
2. Define its normal, loading, empty, offline, error, disabled, and recovery behavior where applicable.
3. State whether it is desktop, mobile, or shared.
4. Reuse the existing token vocabulary.
5. Include a short anti-pattern note.
6. Verify the demo at a wide and narrow viewport.

Do not add:

- Generic component showcases without a real state.
- New accent colors without a semantic reason.
- A second radius system.
- Unlicensed screenshots or copied source.
